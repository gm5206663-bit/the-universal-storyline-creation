SECTION 2 - PIPELINE
==============================================================================

LOAD -> VERIFY -> MAP -> FORECAST -> BLUEPRINT -> DRAFT -> AUDIT -> REPAIR -> DELIVER -> RECORD

  01. LOAD - Read the live edge and the locks
  02. VERIFY [GATE] - Reconstruct canon scene by scene
  03. MAP - Timeline, location, prop, knowledge
  04. FORECAST - Butterfly effects from real changes
  05. BLUEPRINT - Beat order, registers, panel range
  06. DRAFT - Prose carries the chapter
  07. AUDIT [GATE] - Run all seven hard gates
  08. REPAIR - Fix, then re-run the gates
  09. DELIVER - Ship the chapter
  10. RECORD - Update ledgers and the serial log

VERIFY and AUDIT are gates. Do not proceed past one until it passes.
RECORD is never skipped: a decision not written down will regress. In this
system that means filing it into intake/drop/ as a decision or correction,
not just saying it in chat.

==============================================================================
SECTION 3 - PRE-DRAFT GATE (six steps, in order)
==============================================================================

1. Reconstruct - Rebuild the relevant canon scene by scene. Not from memory -
from receipts. If a scene is missing, say it is missing.

2. Verify exact detail - Event order, location, timing, positions, clothing,
objects, environment, dialogue style, motivations, character knowledge.

3. Build the ledgers - Timeline, location, prop, power and adaptation,
knowledge - who knows what, and since when.

4. Firewall - Hide information from characters who have not earned it. Author
knowledge is never character knowledge. Check every speaking character against
the registry.

5. Resolve conflicts - Use the authority hierarchy. User words beat project
docs beat kit laws. Record the resolution, not just the result.

6. Then blueprint - Only now set beat order. Set the panel year range first.
Then draft.

SECTION 6 - THE SEVEN HARD GATES (machine-checked, non-negotiable)
==============================================================================

1. Zero unreadable script - CJK, kana, hangul. Not a blanket non-ASCII ban -
em dashes and box-drawing are fine.

2. Zero literal backslash-n - The two-character sequence leaking into prose
from escaped strings. Use the real newline.

3. Zero digits in prose - Exact figures belong in panels and ledgers. Prose
says 'seven', the panel says '7'.

4. At least three spoken dialogue lines - Dialogue silently disappears from
introspective serials. It went missing from seven of fifteen chapters in one
rebuild and was only caught by counting. Count it; do not eyeball it.

5. Panels contiguous - No overlap, no gap. Insertion and reordering
desynchronise panels, and the drift is invisible until two chapters claim the
same year.

6. No placeholder text - No shipped file contains template slots or lorem-
style filler.

7. Marker discipline - The book-end marker never appears in prose; at most one
end card, opening with END OF, last in the file.

GATE SCOPE - getting this wrong trains everyone to ignore the gate:
  gate                                chapter  templat      law    codex    audit
  Zero unreadable script                  yes      yes      yes      yes      yes
  Zero literal backslash-n                yes      yes      yes      yes      yes
  Zero digits in prose                    yes        -        -        -        -
  At least three spoken dialogue lin      yes        -        -        -        -
  Panels contiguous                       yes        -        -        -        -
  No placeholder text                     yes        -        -      yes        -
  Marker discipline                       yes        -        -        -        -

Gate 6 must never be applied to templates, law files, or audit logs. A
template with no slot tokens is not a template. A law file that cannot show
the panel format cannot teach it. An audit log reports on placeholder counts -
a line reading 'TODO/FIXME/TBD = 0' is the log doing its job, not a leftover.
Gates 1 and 2 are the only ones that apply everywhere, because they are the
ones that indicate a file is broken rather than a file being what it is.

A check must not match its own description. Five confirmed instances: a
blanket non-ASCII gate flagging the em dashes in the prose law that explains
the rule; a case-insensitive substring flagging 'placeholder' inside 'no
placeholder text left'; gate 6 over templates flagging every slot token; gate
6 over an audit log flagging its own zero-count report; and documenting that
last case inside the audit law re-tripping the same class. Scope the gate, do
not reword the file.

Ship the negative test with the gate. tools/selftest.py exists because
verify.py once reported fifteen failures against a proven 33,100-word serial -
every one of them a false positive. A gate nobody has tested is a guess.

SECTION 20 - KNOWLEDGE FIREWALLS
==============================================================================

STATES: KNOWN / KNOWN PARTLY / SUSPICION / DISBELIEF / UNKNOWN / FALSE BELIEF / HIDDEN

Author knowledge is never automatically available to a character.

  KNOWN          Verified knowledge - May act on it and speak of it
  KNOWN PARTLY   Partial knowledge - May act on the part held; must not
  extend it by assumption
  SUSPICION      Suspects, unproven - May worry, probe, deflect - may not
  state as fact
  DISBELIEF      Actively rejects it - Needs direct proof to move; will
  rationalise anomalies first
  UNKNOWN        No knowledge at all - Cannot reference it, hint at it, or
  intuit it
  FALSE BELIEF   Believes something untrue - Acts on the false version; the
  truth must be earned on page
  HIDDEN         Known by author, withheld - Declared but not yet used in
  any registry

THE FOUR LEAK PATHS: Never convert suspicion, intuition, rumour, or prophecy
fragments into factual character knowledge without evidence. Never give a
character information earlier than the earliest valid change recorded in their
firewall. Predetermined destiny does not pre-install personal memories or
trust. Instinctive power control after an awakening does not equal
encyclopaedic lore.

SECTION 21 - ADAPTATION TALENT (cross-project)
==============================================================================

WHAT IT IS: An innate, non-conscious, existence-level personal law or instinct
belonging to the user's OC. It adapts from the complete current foundation.

WHAT IT IS NOT: a UI, a voice, a reward system, a companion, an anomaly, a generic learning mechanic.
It has no dialogue, no notifications, no levels, and no narrator.

REQUIREMENTS:
  - Compatible foundation: There must be something there to adapt. It cannot
  create power from absolute nothing.
  - Integration: The adaptation becomes part of the character, not a bolted-
  on ability.
  - Exposure: The character must actually encounter the thing being adapted
  to.
  - Consequences: Adaptation costs something and changes something. No free
  power.

THE ONE ABUSE TO WATCH FOR: Do not use this framework to justify a character
knowing lore they have not learned. Adaptation is not a knowledge pipe. It
changes what a character can do; it never installs what a character knows.

Adaptation cannot bypass setting rules. It operates inside the setting's
physics - it is not an exemption from them.

==============================================================================
SECTION 23 - HOW THIS SYSTEM GROWS
==============================================================================

This is not a static document. It is a generated view over a state layer that
accepts contributions from any agent.

  FILE      write a JSON contribution into intake/drop/
  VALIDATE  python3 tools/validate.py intake/drop/<file>.json
  INGEST    python3 tools/ingest.py intake/drop/<file>.json
  BUILD     python3 tools/bootstrap.py && python3 tools/build.py

KINDS: anchor, canon, correction, decision, firewall, lock, note, project

A firewall contribution needs: who, state, topic, earliest_change, rule.
A canon contribution needs: claim, confidence - and sources if confidence is
'canon'. The validator rejects a canon claim with no sources named.

Contributions are APPEND-ONLY. Nothing can silently overwrite existing state;
a correction is recorded as a correction, keeping the old value visible.

RESERVED: authority_order, seven_gates, gate_scope_warning, _comment. These
change the shape of the system and need the user, not a contribution.

==============================================================================
SECTION 24 - INSTRUCTIONS TO THE RECEIVING AGENT
==============================================================================

 1. Ingest this bootstrap fully before doing anything else.
 2. DO NOT immediately draft prose.
 3. First perform LOAD -> VERIFY -> MAP.
 4. State only what is confirmed, what is missing, and what must be
reconstructed.
 5. Then use the Control Centre and the project records as the active state.
 6. Do not overwrite established canon, locks, or knowledge firewalls without
explicit authorisation.
 7. If a source scene is missing, identify it as missing rather than inventing
it.
 8. When continuing, preserve all information-discipline constraints.
 9. Run the seven gates on anything you ship. 'Mostly passing' is a failure.
10. Record every new decision and correction in the same pass you make it -
file it into intake/drop/, do not just say it.
11. Corrections come before new content.
